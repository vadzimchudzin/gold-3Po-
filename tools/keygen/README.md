# GOLD3Po-Keygen — автономный генератор лицензий

Одно окно, один exe, без интернета: подписывает ключи `GOLD1.…` приватным ключом
разработчика и ведёт журнал выданного. Ключи побайтово совпадают с теми, что выпускает
`tools/make-key.js`, — приложение их принимает без каких-либо настроек.

## Как этим пользоваться

1. Положить `license-private.pem` **рядом с `GOLD3Po-Keygen.exe`** (или указать путь кнопкой
   «Указать файл…» — он запомнится в `keygen-config.json`).
2. Верхняя строка должна позеленеть: `загружен: license-private.pem`.
   Если она красная — ключ не найден или не Ed25519, выдавать лицензии нельзя.
3. Вставить ID компьютера клиента (16 hex с экрана активации, вид `A8E4-1965-47C1-C929`),
   указать срок в днях и издание.
4. «Выдать ключ» — ключ появится в поле и **сразу скопируется в буфер обмена**,
   а в `license-issued.csv` допишется строка (дата, ID, издание, срок, keyId, сам ключ).
5. Вкладка «Проверить ключ» — вставить любой ключ и убедиться, что он валиден и для какой
   машины/срока выпущен. Проверка идёт по вшитому публичному ключу, приватный для неё не нужен.

## Что важно понимать про передачу программы

Подпись Ed25519 невозможно «разрешить по списку»: **любой, у кого есть exe и
`license-private.pem`, может выпускать неограниченное число лицензий для любых машин.**
Это не недосмотр, а свойство асимметричной криптографии — без приватного ключа не подписать,
а с ним ограничений нет.

Отсюда практические варианты:

| Кому передаём | Что передавать |
|---|---|
| Себе на второй компьютер | exe + pem |
| Доверенный партнёр/дилер | exe + pem, но помните: он получает право выпускать ключи навсегда, и отозвать это нельзя — только сменить корневую пару (тогда умрут все ранее выданные ключи) |
| Партнёр, которому нужны лимиты | не exe, а серверный выпуск: pem остаётся у вас, партнёр получает доступ к форме с квотой. Это отдельная задача, exe её не решает |
| Покупатель программы целиком | exe + pem + журнал `license-issued.csv`, чтобы он видел, кому что выдано |

Если приватный ключ утёк — единственное лечение: `npm run license:init` на своей машине,
новый публичный ключ в `license.js`, новая сборка. Все старые ключи после этого перестают
работать, и клиентам нужно выдать новые.

## Файлы рядом с программой

| Файл | Что это |
|---|---|
| `license-private.pem` | приватный ключ Ed25519 (никогда не в git, храните с бэкапом) |
| `keygen-config.json` | запомненный путь к ключу, создаётся автоматически |
| `license-issued.csv` | журнал выданных ключей, дописывается после каждой выдачи |

## Самопроверка без окна

```powershell
GOLD3Po-Keygen.exe --selftest license-private.pem report.json
```

Пишет JSON: `valid`, `other_machine`, `tampered`, `matches_embedded_key`. Последнее поле —
ответ на вопрос «подходит ли этот pem к текущей сборке приложения»: `true` означает, что
выпущенные ключи приложение примет.

## Тесты

```bash
python -m unittest discover -s tools/keygen -p "test_*.py"
```

Проверяют порядок полей payload (он входит в подпись), отказ для чужой машины, порчу подписи,
просрочку, обрезанный ключ и неверные входные данные.
